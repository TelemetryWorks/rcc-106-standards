## Method and commands

Python 3.11+ standard library and the existing authenticated GitHub CLI were
used. No packages were installed and no archived document or executable ran.

```powershell
python scripts/audit_mirror.py --output files/audits/2026-11-03
python scripts/audit_mirror.py --output files/audits/2026-11-03 --resume
python -m unittest discover -s scripts -p test_audit_mirror.py
git diff --check
```

The command enumerates **all** releases and every release's asset endpoint
with `gh api --paginate --slurp`, using `per_page=100`. Two workers bound
inventory requests; two workers bound asset downloads. For each asset,
`urllib.request.urlopen` follows its public GitHub release URL and reads in
1 MiB blocks, hashing the received bytes. No official-source fallback or
local-document cache is used. All 741 original mirror URLs equal the
corresponding inventory download URL and have the expected repository,
release tag and asset path. All final responses were HTTP 200, terminating
on `release-assets.githubusercontent.com`.

Each checkpoint records release/name, asset ID, original public URL, UTC
timestamps, HTTP status, final hostname, response headers, observed size,
observed SHA-256, attempt count and outcome. Redirect query strings and
credentials are not recorded. Received hashes were compared both with the
manifest and with GitHub's independently listed asset digests.

Before/after inventories are identical. Their canonical JSON SHA-256 is
`7d8d24ebb52f353fad08944c34be50d9d9be88a40ea620a3d81a90dcf5d4c07c`.
The corrected final reconciliation reused the 741 fresh download checkpoints
only after rechecking the unchanged manifest and complete inventory binding;
it did not repeat the body downloads. The 741-file cross-join was also checked
independently of the audit command's generated summary.

## Review and limitations

The initial classifier incorrectly treated the 33 intentional local filename
mappings as failures. It was corrected, the original classification outputs
were preserved, and final results were regenerated from the same remote-byte
evidence. This was an audit-tool issue, not a published-asset discrepancy.
Coordinator review also required extra assets, duplicate remote names and
absent download evidence to fail the command; focused offline tests cover
these cases.

Ten offline tests pass: received-byte hashing and filename mapping, same-size
wrong content, truncation, missing asset, extra asset, duplicate extra names,
duplicate expected names, absent download evidence, inventory change, and
bound checkpoint resume. The resume test also rejects changed audit inputs.

The coordinator independently cross-joined all 741 manifest records with the
before/after inventories and received-byte checkpoints without importing the
audit command. That review confirmed every URL, size, SHA-256 and API digest,
all HTTP 200 responses, the distinct-blob counts and byte totals, no extras or
duplicates, and unchanged inventories. The coordinator also independently
verified the evidence ZIP's SHA-256/integrity and reran all ten offline tests
successfully, then approved the report, command and tests on 2026-11-03.

739 assets completed on attempt 1; two completed on attempt 2. The original
checkpoint format retains final outcomes and attempt counts, but not the
first failed attempts' exception details. All final received bytes match.

This audit establishes the GitHub mirror against the pinned manifest at the
stated time. It does not establish correctness of document contents against
issuing organizations, completeness beyond the manifest, schema semantics,
or validity of distribution markings. No authoritative-source discrepancy
investigation or asset repair was needed. This work adds no CI or documents.
